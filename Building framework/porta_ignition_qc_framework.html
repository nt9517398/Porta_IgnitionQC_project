1. Project Intent & Executive Summary

The primary objective of this project is to completely replace controlled paper logs and manual Excel spreadsheets across the Myrtleford mill floor with authenticated, station-aware Ignition Perspective web forms backed by a high-performance central relational SQL database. This document serves as the unified technical directive, mapping all floor operations to robust digital parameters.

The unified platform is built as an extensible, configuration-driven plant-wide quality management engine. A shared database schema and script configuration library handle form definitions, dynamic tolerance validation layers, real-time alert triggers, and manager authorization matrices seamlessly across all production stations.

2. User Roles, Journeys & Access Matrix

The system simplifies complex, multi-tiered role structures into two core functional application identities, separating shop floor data capture from administrative management tools.

Function Scope QC Technician QC Manager System Admin / Developer

6. Core Technical Configuration Schema

All process checks are dynamically bound to a relational database configuration. Under the single-file layout directive, table schemas are normalized to support modular form expansions with zero runtime code modifications.

Table Entity Name Structural Purpose Key Relationships & Constraints
qc_form_definition Main registry for all physical mill logging sheets. Primary key: form_id.
qc_form_revision Tracks revision lifecycle states (DRAFT, ACTIVE, SUPERSEDED). Foreign key: form_id.
qc_specification Stores engineering constraints, warning bands, and targets. Foreign key: revision_id. Snapshots limits on raw submits.
qc_inspection Core transaction log capturing user, context, and overall status. Primary key: inspection_id.
qc_measurement Saves individual input data and local deviation properties. Foreign key: inspection_id.
